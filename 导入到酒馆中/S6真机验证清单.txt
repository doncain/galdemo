minigal · S6 真机验证清单（全屏守卫 + 锁定前端）
========================================================

S6 做什么
--------------------------------------------------------
两件事，其中守卫部分（伪全屏 + 高度自适应）之前已经做完并验过，
这一次补的是**独立的「锁定前端」脚本**：

  全屏玩的时候，酒馆还会做两件对我们致命的事 ——
    · 往聊天里塞新楼层 → 伪全屏的布局被挤开
    · 重新渲染时拆掉旧楼层的 iframe → 游戏白屏，而且是在玩家全屏时白屏

  锁定前端就是挡这两件事：藏掉其它楼层 + 保护锁定楼的 iframe 不被删。

它是**可选**的独立脚本。不装也能玩，只是全屏时没有这层保护。

--------------------------------------------------------
 准备
--------------------------------------------------------
1. 项目根目录跑本地服务：

     node scripts/serve.mjs

2. 先确认基础功能正常：酒馆里能显示画面、楼层条显示「酒馆 第 N 楼」。

3. 导入锁定脚本（两种方式任选）：

   【正式方式】导入 导入到酒馆中/minigal-锁定前端.json
     —— 在酒馆助手的**脚本库**里导入（与界面正则不是同一个入口）。

   【本机迭代】在脚本库里手工新建一个脚本，内容只写一行：

     import 'http://localhost:5173/dist/minigal-lock/index.js';

     改代码后重建（npm run build）→ 刷新页面即可生效，不用等 CDN。

--------------------------------------------------------
 第 0 步：确认脚本真的加载了
--------------------------------------------------------
打开浏览器 DevTools 的 Console，应当看到类似：

  [minigal] 锁定前端：已锁定第 N 楼

（进入全屏时才会出现；没进全屏时什么都不会打印，这是正常的。）

★ 如果 console 报了「拿不到酒馆页面上下文」，把截图给我 ——
  说明脚本被注入到了一个访问不到主页面 document 的位置。

--------------------------------------------------------
 ① 全屏：其余楼层被藏掉
--------------------------------------------------------
操作：点开发条或楼层条上的「全屏」。

要看到：
  · 画面铺满，**除了游戏看不到任何其它楼层**
  · DevTools 里 `document.head` 多了一个
    `<style id="minigal-lock-floor-style">`
    内容是 `.mes:not([mesid="N"]) { display: none !important }`

★ 注意：原生全屏**可能被浏览器拒绝**（这是常态）。被拒绝时上面的
  「伪全屏」照样生效 —— 而锁定脚本靠的不是原生全屏事件，是我们主动通报的，
  所以两种情况都应当锁上。如果只有「屏幕没变大」而没有锁定，告诉我。

--------------------------------------------------------
 ② 全屏期间来了新楼层：画面不许动
--------------------------------------------------------
操作：保持全屏，想办法让聊天里多出新楼（比如在酒馆侧边栏手动插入一楼，
或者让另一个标签页/脚本发条消息）。

要看到：
  · 新楼层**不出现**在画面上（被藏住了）
  · 你的游戏画面纹丝不动、没有被挤开

--------------------------------------------------------
 ③ 全屏期间尝试删除锁定楼：应当被拒
--------------------------------------------------------
操作：全屏状态下，用酒馆自己的删楼功能删掉**你正在玩的那一楼**。

要看到：
  · 楼层没被删掉
  · 游戏继续正常玩，**没有白屏**

★ 对照实验（**这一步很重要，别省**）：
  退出全屏后，再删一次同一楼层 —— 这次**应当真的删掉**。
  如果退出全屏后也删不掉，说明拦截没有正确解除，那是更严重的问题（告诉我）。
  反过来，如果全屏时也删得掉，说明拦截没生效。

  两个方向都要试，否则你无法分辨「拦住了」和「本来就删不掉」。

--------------------------------------------------------
 ④ 退出全屏：一切复原
--------------------------------------------------------
操作：按 Esc，或点「退出全屏」。

要看到：
  · 所有楼层恢复显示（**包括你在全屏期间新增的那些**）
  · 游戏的 iframe 高度正常（不塌缩、不出双滚动条）
  · DevTools 里 `minigal-lock-floor-style` 和 `minigal-lock-protect-script`
    都消失了

★ 特别注意第 1 条：全屏期间新增的楼层如果退出后仍然看不见，
  那是「隐藏没撤销」——锁定期我们给新楼层打过 inline 隐藏，退出时必须撤掉。
  这是本脚本里最容易漏的一步，请务必看一眼。

--------------------------------------------------------
 ⑤ 卸载脚本：不能留下后遗症
--------------------------------------------------------
操作：在脚本库里**禁用**锁定前端脚本，然后尝试删楼、改楼层。

要看到：
  · 删楼恢复正常（脚本卸载时必须把三个被替换的 API 还原）
  · 不会出现「酒馆突然删不掉任何东西」这种更糟的情况

--------------------------------------------------------
 出问题时给我什么
--------------------------------------------------------
1. Console 里的 `[minigal] 锁定前端` 那几行（一条都不要漏）
2. 你做到第几步、期望看到什么、实际看到什么
3. DevTools 里 `document.head` 的截图（有没有那两个 style/script）

--------------------------------------------------------
 已知的、可以忽略的现象
--------------------------------------------------------
· 原生全屏没生效（屏幕没变大）—— 被浏览器策略拒绝是常态，伪全屏兜底
· console 里没有锁定日志 —— 你还没进全屏，或者脚本没加载
· 底部那一整条开发信息 —— 开发期用的，玩家不该看到，后续会加开关隐藏

--------------------------------------------------------
 我这边的自动化覆盖到哪、没覆盖到哪（如实说明）
--------------------------------------------------------
已覆盖（本地，全部通过）：
  · 在一个**假酒馆**里造了多楼层 + 楼层 iframe，验证：
      - 锁定时其它楼层被藏、锁定楼自己不被藏
      - 锁定期新增楼层被藏（CSS 规则 + 观察者兜底两条路径分别验）
      - 样式被清掉后能补回来
      - 三条删除路径全部拦住（iframe.remove / removeChild / 嵌套 removeChild / jQuery.remove）
      - **同一次 jQuery 调用里，没被锁的楼层照删**（证明是选择性拦截，不是把 remove 废掉）
      - 未被锁的楼层照旧可删（定向性）
      - 解锁后全部还原（含撤销 inline 隐藏）
      - **对照实验**：解锁后同样的删除调用必须真的生效
      - 「先全屏、脚本后加载」的补锁路径
  · 交付自检 58 条（含锁定脚本产物非空壳、地址钉提交号、两份 JSON 的 id 不冲突）

没覆盖（写出来免得你以为验过了）：
  · 真酒馆的楼层 DOM 结构与它实际的删除路径 —— 就是本清单要你做的部分
  · 原生全屏成功时的 `fullscreenchange` 路径（无头环境里无法真正进入原生全屏）
  · 移动端真机
