========================================================
 minigal · 导入说明
 把楼层文本变成 galgame 界面
========================================================

这个包做什么
--------------------------------------------------------
目标：AI 输出的每一层楼文，不再是一段普通文字，
而是被渲染成一个 galgame 画面：名字牌、对话框、打字机效果、
情绪标签、背景与立绘、选项按钮。

原理一句话：楼层文本 → 正则整段替换成一段带围栏的代码块
→ 酒馆助手把代码块提升为 iframe → iframe 里拉取单文件 HTML 渲染。

注意：正则只改「显示层」。发给 AI 的还是原始文本，
所以变量解析、回看历史一切照旧，不会因为装了界面而失效。

--------------------------------------------------------
 ★ 当前进度：界面能显示，但还不会「演绎你的文本」
--------------------------------------------------------

  现状要如实说明，免得你照着下面验证时困惑：

  已完成的：
    ✔ 解析器（楼层文本 → 可播数据）
    ✔ 文本框 / 名牌 / 情绪标签 / 打字机 / 翻页 / 选项面板
    ✔ 背景 CG 层 + 三槽位立绘舞台（说话人亮、旁听暗、同屏 ≤3）
    ✔ 交付层：正则替换、单文件产物、CDN 发布通道（已上线并实测）

  尚未完成的（关键）：
    ✘ **前端还没有接入酒馆数据**。它现在读的是内置的演示脚本，
      不是你在酒馆里那一楼的实际文本。

  所以现在导入后你会看到：一个能正常播、能翻页、有立绘和背景的
  demo 界面——但无论 AI 输出什么，画面内容都是同一个演示脚本。

  为什么必须这样设计（不是偷懒）：
    正则把整段楼层文本替换成了 iframe，所以 iframe 里**看不到**
    那段文本了。它要通过酒馆助手注入的 API 主动去「读回」本楼原文。
    这个「回读 + 楼层导航 + 真实发送」就是下一个开发阶段要做的事
    ——权威文档里叫「阶段三 / §S4 接入酒馆」。

  接入之后，本说明的「第四步：验证装好了」那一节才会真正成立。
  在那之前，用本节的状态来判断，别用第四步。

--------------------------------------------------------
 ★ 那现在能验收什么？（三件事，都可立刻做）
--------------------------------------------------------

  ① 投递链路 —— 已经通了
     你能看到界面，就说明这条链路整条是通的：
       正则命中 → 酒馆助手提升为 iframe → CDN 拉到单文件 → 渲染出画面
     这也正是「正式版」上线前要验的东西，结论：通过。

  ② API 探针 —— 现在最该做的一步（约 1 分钟）
     界面底部开发条右侧有个「探 API」按钮，点它。

     它检查酒馆助手是否把 TavernHelper 的函数注入了 iframe
     （getChatMessages / eventOn / triggerSlash / generate …）。
     **S4 整个阶段都建立在这些函数之上**，先确认它们在，
     能避免照着文档写完代码才发现某个 API 改名了。

     怎么读结果：
       · 三条绿色结论 → 核心函数齐全，S4 可以按文档开工
       · 黄色 → 缺了核心函数，需要找等价 API（把缺失的名字告诉我）
       · 红色「当前不在 iframe 语境里」→ 说明这次不是在酒馆里点的，
         换到酒馆楼层界面里再点一次

     注意：探针只证明 API「存在」，不证明「行为正确」。
     真实发送、翻楼、重生成这些行为契约，要等 S4 做完才能验。

     也可以在地址后加 ?probe=1 让它自动跑一次。

  ③ 剧本协议 —— 在酒馆之外就能验
     用项目里的预览工具，把任意文本喂给同一条渲染链路：

       node scripts/preview-floor.mjs 你的剧本.txt

     输出截图 + 解析摘要（行数/选项/场景/说话人/缺情绪标注的行）。
     适合调协议写法：改一句、看一眼，不用推 CDN、不用开酒馆。

     它会同时暴露「名字没登记」的问题（见下面的第五步之二）。

--------------------------------------------------------
 第一步：把两个文件导入酒馆
--------------------------------------------------------
打开 酒馆 → 扩展/界面正则（酒馆助手的正则列表），
分别导入本目录下的两个 json：

  minigal-界面-正式.json      ← 默认启用，玩家用这个（走 CDN）
  minigal-界面-实时修改.json  ← 默认禁用，开发时用（走本机）

两个文件里的 scriptName 都是「minigal-界面」，这是有意的：
它们是同一个正则的两种部署形态，你同一时间只该启用其中一个。

--------------------------------------------------------
 第二步：确认「正式版」的地址是通的
--------------------------------------------------------
正式版 json 里的地址形如：

  https://cdn.jsdelivr.net/gh/<user>/<repo>@master/dist/yaoguai/minigal/index.html

★ 如果你打开文件看到 REPLACE_ME_USER / REPLACE_ME_REPO，
  说明仓库地址还没填。这个文件此时不能用于交付，
  必须先把 <user>/<repo> 换成真实的 GitHub 仓库，
  并确保 dist/yaoguai/minigal/index.html 已经推到那个仓库。

怎么自查这一步有没有做完：
  node scripts/verify-delivery.mjs
  看到「正式 · CDN 地址已填真实仓库」是 PASS 才算好。

--------------------------------------------------------
 第三步（可选）：本地开发时怎么改
--------------------------------------------------------
改样式 / 改解析器的时候，不想每改一次就推一次代码等 CDN，
就切换到本机通道：

  1. 启动本地服务（在项目根目录）：
       node scripts/serve.mjs
     它会打印一个地址，形如
       http://localhost:5173/dist/yaoguai/minigal/index.html

  2. 酒馆正则列表里：
       禁用「minigal-界面-正式.json」
       启用「minigal-界面-实时修改.json」

  3. 改完代码后重新构建：
       npm run build
     然后在酒馆里刷新一下楼层（重 roll 或切楼层再切回来）就能看到新效果。

  4. 调试完切回正式版：启用正式、禁用实时。

注意：本地服务开了 CORS 且禁了缓存。这是本机开发用的，
不要把它开在对公网开放的机器上。

--------------------------------------------------------
 第四步：验证装好了
--------------------------------------------------------

★ 先看上文「当前进度」——**在「接入酒馆」完成之前，本节不适用**。
  现在按本节操作，你会看到界面正常播放，但播的是内置演示脚本，
  跟你发的文本无关。那是已知的未完成项，不是装错了。

    快速自查：如果界面左下/右下有「夹具 s1」之类的开发条文字，
    说明跑的是演示夹具。

以下内容在接入酒馆完成后才成立。

在酒馆里发一条消息，让 AI 输出一段符合剧本协议的文本，
例如：

  [scene:旧城区/河堤/柳树下]
  夜里的河风把芦苇压向一边。青梧站在柳影里，没有回头。
  青梧[平静]:"你走路的动静，三条街外就听见了。"
  我[平静]:"我只是路过。"

看到的应该是：
  · 左上角有场景标签
  · 底部有对话框，说话人名字牌 + 情绪小胶囊
  · 文字逐字打出来（点一下可以跳过打字）
  · 旁白行没有名字牌、没有情绪标签

看不到界面时的排查顺序（从最可能到最不可能）：
  ① 楼层里有没有内容？空楼不会有任何变化。
  ② 用的是哪条正则？正式版通了没有？（可能 CDN 还没回源，等 30 秒再试）
  ③ 用本地版试试，还不行说明问题在正则或酒馆助手，不在 CDN。
  ④ 打开浏览器 DevTools，看 iframe 里有没有报错。

--------------------------------------------------------
 第五步：剧本要怎么写
--------------------------------------------------------
界面能正确渲染的前提是 AI 按协议输出。协议要点：

  对话    角色名[情绪]:"台词"
  玩家    我[情绪]:"台词"        （也可以写 <user>[情绪]:"台词"）
  独白    角色名[情绪]:*心里话*
  旁白    直接写，不加任何标记
  换景    [scene:父/子/末级]     独占一行

三条容易写错、后果明显的规则：

  ① 旁白 = 纯客观描写。
     不要写台词、不要带引号、不要写心理活动。
     想写「他说了一句话」，就写成对话行，让引语归位。

       错：他笑了笑:"我什么都没看见。"——这话是对着河面说的。
       对：他笑了笑，把话咽了回去，目光移向河面。
           青梧[平静]:"我什么都没看见。"

  ② 对话行必须带 [情绪] 方括号。
     忘了写方括号，那一行会被当成旁白——台词会以旁白样式出现，
     而且带引号，看起来很奇怪。
     前端会把这种行标记出来（显示一条琥珀色提示条），
     但那只是提醒，不会替你修好。

  ③ 情绪名用中文：平静 / 微笑 / 开心 / 生气 / 害羞 /
     悲伤 / 惊讶 / 害怕 / 无奈 / 冷淡 / 认真 / 困惑。
     写了别的词不会崩，会按默认情绪（平静）处理，
     界面上用虚线灰框表示「这是兜底值，不是作者写的」。

--------------------------------------------------------
 第五步之二：角色与场景要先「登记」，才有立绘和背景
--------------------------------------------------------

光有剧本还不够，还有一张表要填。渲染流程是：

    文本里的名字  →  查表  →  图片

查不到就**降级，不报错**：

    角色名查不到  →  该角色没有立绘（占位不出图）
    场景路径查不到 →  保留上一张背景，场景标签旁显示橙色「无背景」

实测过：写一个表里没有的角色（如「老周」）和场景（如「城南/废弃车站」），
画面能正常播，但开发条会显示「未登记 老周」、场景标签旁出现「无背景」。
**这时候你会以为界面坏了，其实只是没登记。**

登记位置：src/yaoguai/minigal/core/assets.ts

    CHARACTERS  角色表 —— 名字 + 有哪些情绪差分
    SCENES      场景表 —— 路径，必须与 [scene:] 里写的完全一致

当前这两张表里只有演示用的条目（青梧/沈砚/阿棠、旧城区系列）。
**写自己的故事时，把它们换成你自己的角色与场景。**

两个容易踩的点：

  · 场景路径是**逐级向上回退**的：
      表里登记了「旧城区/河堤」，那 [scene:旧城区/河堤/柳树下/西岸]
      会命中「旧城区/河堤」。所以不必把每个末级地点都登记全。
    （但方向只向上，不向下——登记了末级，写父级是查不到的。）

  · 立绘与背景的占位图是**程序生成的**，不是真图片：
      图上会写角色名和情绪名，方便你核对状态机切换是否正确。
      想换真图，把两张表的 value 换成图片直链即可，
      其余代码一行都不用改（assets.ts 末尾有说明）。

--------------------------------------------------------
 附：日常更新（改完代码要让玩家看到）
--------------------------------------------------------
  ① npm run build          构建（不构建就发布=推旧文件）
  ② node scripts/publish.mjs --dry-run    先检查
  ③ node scripts/publish.mjs              提交并推送
  ④ 按脚本打印的提示，核对 CDN 字节数与 SHA-256
  ⑤ 需要立刻生效时，打开脚本给出的 purge 链接刷缓存
     （不刷则玩家最多 12 小时内自动拿到新版）

两个容易出事的点：
  · 构建和发布不要串在同一条命令里。让构建完整跑完，再单独发布。
  · 发布后一定要核对字节数。推送成功不等于 CDN 已生效。
